# 🔄 Система Автоматических Повторных Попыток

## 📋 Описание

Система автоматически обрабатывает неудавшиеся заказы при ошибках Fragment API и повторяет попытки начисления звёзд.

## ✨ Основные возможности

### 1. **Автоматическое добавление в очередь**
- При ошибке Fragment API заказ автоматически добавляется в JSON файл
- Проверка на дубликаты перед добавлением
- Классификация ошибок для определения стратегии

### 2. **Защита от дублирования**
- ✅ Проверка по `orderId` перед добавлением в очередь
- ✅ Сохранение `lastSuccessfulFragmentOrderId` после успешного выполнения
- ✅ Двойная проверка перед начислением звёзд
- ✅ Невозможно начислить звёзды дважды одному пользователю

### 3. **Автоматическая обработка**
- Запуск каждые 2 минуты через cron
- До 10 попыток на заказ
- Экспоненциальная задержка между попытками
- Уведомления пользователей о статусе

### 4. **Умная классификация ошибок**

#### Повторяемые ошибки (будут повторяться):
- `FRAGMENT_SSL_ERROR` - SSL/TLS ошибки
- `FRAGMENT_TIMEOUT` - Таймауты
- `FRAGMENT_UNAVAILABLE` - Сервис недоступен
- `FRAGMENT_RATE_LIMIT` - Превышен лимит запросов
- `UNKNOWN_ERROR` - Неизвестные ошибки

#### НЕ повторяемые ошибки (не будут повторяться):
- `FRAGMENT_USER_NOT_FOUND` - Пользователь не найден
- `FRAGMENT_INSUFFICIENT_BALANCE` - Недостаточно баланса

## 🔧 Как это работает

### 1. Когда заказ проваливается:

```typescript
// В KassaWebhookService при ошибке Fragment API
await retryQueueService.addFailedOrder(
  orderId,          // ID заказа
  userId,           // Telegram User ID
  chatId,           // Telegram Chat ID
  recipientUsername, // Username получателя
  starsCount,       // Количество звёзд
  isGift,           // Подарок или нет
  failureReason,    // Причина ошибки
  errorMessage,     // Текст ошибки
  'P2PKassa',       // Метод оплаты
  amount,           // Сумма
  currency,         // Валюта
  transactionId     // ID транзакции
);
```

### 2. Автоматическая проверка каждые 2 минуты:

```typescript
@Cron('*/2 * * * *')  // Каждые 2 минуты
async handleRetryQueue() {
  await retryQueueService.processRetryQueue();
}
```

### 3. Защита от дублирования:

```typescript
// Проверка 1: При добавлении в очередь
if (queue.find(order => order.orderId === orderId)) {
  return; // Уже есть в очереди
}

// Проверка 2: Перед начислением звёзд
if (order.lastSuccessfulFragmentOrderId) {
  return; // Уже успешно выполнен
}

// Проверка 3: После успешного начисления
order.lastSuccessfulFragmentOrderId = fragmentOrder.id;
```

## 🎯 Статусы заказов

- `pending` - Ожидает обработки
- `retrying` - В процессе повторной попытки
- `completed` - Успешно выполнен ✅
- `failed` - Окончательно провален ❌

## 🛠️ Обслуживание

### Автоматическая очистка
Каждый день в 3:00 ночи удаляются завершённые заказы старше 7 дней:
```typescript
@Cron('0 3 * * *')
async handleCleanup() {
  await retryQueueService.cleanupOldOrders(7);
}
```

### Ручная проверка очереди
Файл очереди находится здесь:
```
/app/data/retry-queue.json  (Docker)
./data/retry-queue.json     (локально)
```

## 🔐 Безопасность

1. **Защита от дублирования** - многоуровневая проверка
2. **Блокировка обработки** - `isProcessing` флаг предотвращает одновременную обработку
3. **Сохранение Fragment Order ID** - после успешного начисления невозможно повторить
