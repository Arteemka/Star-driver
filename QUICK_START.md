## ⚡ Основные возможности

### ✅ Уже работает автоматически:
1. **Добавление в очередь** - при любой ошибке Fragment API
2. **Повторные попытки** - каждые 2 минуты
3. **Защита от дублирования** - невозможно начислить дважды
4. **Уведомления пользователей** - на каждом этапе
5. **Очистка старых заказов** - каждый день в 3:00

### ⚙️ Настройки (в коде):
```typescript
// retry-queue.service.ts
MAX_ATTEMPTS = 10              // Максимум попыток
RETRY_DELAY_MS = 2 * 60 * 1000 // 2 минуты между попытками

// retry-scheduler.service.ts
@Cron('*/2 * * * *')           // Каждые 2 минуты
@Cron('0 3 * * *')             // Очистка в 3:00

// retry-queue.service.ts:cleanupOldOrders
daysOld = 7                    // Удалять старше 7 дней
```

## 🛡️ Защита от дублирования

Система имеет **3 уровня защиты**:

1. **При добавлении в очередь**
   ```typescript
   if (existingOrder) {
     return; // Уже есть в очереди
   }
   ```

2. **Перед начислением звёзд**
   ```typescript
   if (order.lastSuccessfulFragmentOrderId) {
     return; // Уже успешно выполнен
   }
   ```

3. **После успешного начисления**
   ```typescript
   order.lastSuccessfulFragmentOrderId = fragmentOrder.id;
   // Теперь невозможно повторить!
   ```

## ❓ Частые вопросы

**Q: Что делать, если очередь не работает?**
A: Проверьте логи на ошибки при старте приложения

**Q: Как очистить очередь вручную?**
A: Просто удалите файл `data/retry-queue.json`

**Q: Можно ли изменить частоту проверки?**
A: Да, измените cron в `retry-scheduler.service.ts` (строка 30)

**Q: Можно ли увеличить количество попыток?**
A: Да, измените `MAX_ATTEMPTS` в `retry-queue.service.ts` (строка 26)

**Q: Как посмотреть, сколько заказов в очереди?**
A: Проверьте логи или откройте файл `data/retry-queue.json`
